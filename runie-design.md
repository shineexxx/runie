## Problem Statement

Claude Code умеет всё, что нужно агенту: многошаговые задачи, инструменты, MCP, разрешения, память сессий, skills. Не хватает человеческого интерфейса для не-программиста, который хочет ассистента для повседневных задач на Mac, а не панель для кодинга.

Исходный концепт ([runie-concept.md](/Users/arseny/Projects/runie/runie-concept.md)) формулировал это как «Eney от MacPaw, но открытый и бесплатный, потому что подписка уже оплачена». Сессия показала, что эта формулировка слабая и проигрышная — см. Premises.

## What Makes This Cool

Выбранный вау-момент (двойной):

1. **Видимые руки по настоящему Mac.** Пользователь смотрит, как Runie открывает Finder, двигает файлы, жмёт кнопки в чужих приложениях. Это снимается на 30-секундную гифку и не путается с очередным окном чата.
2. **Каталог навыков в один клик.** Поставил навык — ассистент сразу умеет новое.

**Главный вывод сессии (eureka).** Все конкуренты строят ассистента как *набор инструментов*. У Dottie 134 инструмента, вшитых в бинарь: 135-й означает PR в чужое приложение, ревью, сборку, релиз. Runie не должен соревноваться количеством. Его способности — не код внутри приложения, а `~/.claude/skills` и MCP-конфиг: папка с markdown-файлами.

Отсюда следует то, чего нет ни у кого: **любой skill и любой MCP-сервер, написанный для Claude Code где угодно, работает в Runie в день написания.** Экосистема уже существует и растёт без участия автора. Dottie этого не догонит, потому что её инструменты — это её код.

Правильная первая строка README: *ассистент для Mac, который расширяется markdown-файлом, и которому достаётся вся экосистема Claude Code бесплатно.*

## Constraints

- Swift/SwiftUI, без Electron. macOS.
- Весь интеллект через процесс `claude`. Проект никогда не трогает OAuth-токены и не ходит в API напрямую.
- MIT, ноль телеметрии, ноль аккаунтов, ноль серверов проекта.
- Своей базы нет: история и продолжение сессий через `--resume` там, где их уже хранит Claude Code.
- В названии и материалах нет слова «Claude».
- Один разработчик, кода на момент сессии не существует.

## Landscape (проверено поиском, сентябрь 2026)

Утверждение концепта «ниша пуста» **неверно в той формулировке, в которой было написано**.

- **[Dottie](https://www.dottie.ai/)** — бесплатный, open source, Mac-нативный агент. 134 системных инструмента, голос по Option+Space, плавающая панель, без аккаунта, BYO-модель, local-first, Apple Silicon + macOS 15.4+. Это почти дословно абзац «Что видит пользователь» из концепта, уже отгруженный.
- **[Clarc](https://github.com/ttnear/Clarc)** — нативный SwiftUI-клиент Claude Code. Заявленная причина существования: «чтобы не-разработчики-коллеги могли пользоваться Claude Code, не изучая шелл». Но он репозиторно-ориентированный: дерево файлов, git, диффы, встроенный терминал. Лицензия **Apache-2.0**, не MIT: копирование его кода в MIT-проект тянет за собой сохранение лицензии и NOTICE для этих файлов, поэтому Clarc — референс для чтения, а не донор кода.
- Плюс россыпь menubar-приложений для мониторинга лимитов (ClaudeBar и прочие) — не конкуренты, но занимают ту же иконку в menubar.

Что действительно пусто: **Claude Code как мозг ассистента для не-программиста, с расширением через файлы, а не через код.**

### Платформенный риск (подтверждено первоисточниками)

- 15 июня 2026 Anthropic объявил вынос Agent SDK, `claude -p` и **third-party app usage** в отдельный кредитный пул ($20 Pro / $100 Max 5x / $200 Max 20x) и **отменил в тот же день**.
- Официальная страница сейчас: *"nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits"*, план **перерабатывается** ([Claude Help Center](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)).
- Пункт 7 consumer terms запрещает доступ «through automated or non-human means… except when accessing via an Anthropic API Key». Issue [anthropics/claude-code#36324](https://github.com/anthropics/claude-code/issues/36324) с просьбой предупредить об этом в документации headless-режима закрыт как not planned.

Хорошая новость: формулировка про *third-party app usage* прямо легализует приложения вроде Runie. Плохая: она уже один раз была отменена и будет пересматриваться.

## Premises

Все приняты пользователем в ходе сессии.

**P1 — позиционирование.** Главное отличие Runie — не «бесплатный Eney» и не количество инструментов, а субстрат расширения: навык добавляется markdown-файлом без сборки, и вся существующая экосистема skills и MCP для Claude Code работает сразу. *Почему:* при позиционировании «ассистент с инструментами» счёт против Dottie 134:0 с первого дня.

**P2 — платформенный риск.** Зависимость от того, что `claude -p` останется покрыт подпиской, — главный риск проекта, и его надо заложить в архитектуру (граница ±один агентский CLI), а не в абзац про принципы. *Почему:* одно решение чужой компании о биллинге иначе убивает проект за ночь.

**P3 — проактивность (смягчена после возражения Codex).** Фоновые запуски `claude` по таймеру — **самая рискованная** часть концепта относительно запрета «automated or non-human means». Проактивность строится на событиях присутствия человека (разблокировка, открытие окна, явный клик), а не на cron. *Почему:* первый забаненный пользователь в issues даёт открытому проекту репутацию «через него банят».

*История формулировки:* изначально P3 говорила «единственная часть, которая трогает запрет». Codex возразил, что регулярный вызов headless `claude -p` из GUI тоже может быть квалифицирован как automated means даже по клику. Слово «единственная» недоказуемо, поэтому убрано. Архитектурный вывод про события присутствия сохранён без изменений.

## Cross-Model Perspective

Независимый холодный прогон через Codex CLI. Оговорка: `gpt-6-astra` не поддерживается установленной версией CLI, прогон ушёл на дефолтную модель, точная модель неизвестна — вес соответствующий.

- **Teach Mode.** Пользователь показывает задачу один раз, Runie смотрит дерево Accessibility-действий и сохраняет читаемый «Mac-рецепт» как навык. Воспроизводит семантически («открой эту папку в Finder», «приложи эти файлы»), показывает dry-run diff, пакует нужные MCP-серверы и разрешения. Соединяет оба выбранных вау-момента в один.
- **Главный сигнал сессии:** реплика `"+ еще mcp сервера"`. После выбора трёх пользовательских автоматизаций человек без запроса добавил заботу об экосистеме. Азарт не в том, что ассистент делает дела, а в том, чтобы превратить мир расширений Claude Code во что-то, что обычный пользователь Mac может посмотреть, которому доверяет, ставит и использует.
- **Clarc даёт ~50%.** Оставшиеся 50% и есть продукт: брокер способностей и разрешений, управление Mac через Accessibility, человекочитаемый UI действий, безопасные сценарии с файлами и отправкой, установщик MCP и навыков для нетехнического человека. Dottie — дополняющий референс по нативной автоматизации, но без субстрата расширения.
- **Скелет на выходные:** `AgentRuntime` (один Process, пайпы, NDJSON-декодер, хранение session id) → `AgentProtocol` (нормализация в assistantText / toolUse / toolResult / permissionRequest / completed / failed) → `CapabilityBroker` (ровно два инструмента: files и accessibility, подтверждение на каждое действие) → `RunieApp` (чат, лента «рук», лист разрешений, установка MCP из URL). Демо-путь: «сожми вчерашние скриншоты и отправь Саше», со стопом перед отправкой.
- **Оспорил P3** (см. выше).

Где я согласен: Teach Mode сильнее моей формулировки — markdown-файл пишет сам Runie, наблюдая за пользователем, значит каталог наполняют пользователи, а не программисты. Clarc как референс; писать свой рантайм, потому что он Apache-2.0, а не MIT.

Где не согласен: Codex предложил пропустить Mail и Calendar в первой итерации. Утренний разбор дня — один из трёх выбранных сценариев, а Calendar через AppleScript это часы, не дни.

## Approaches Considered

### Approach A: Тонкий клиент — отклонён
`AgentRuntime` + `AgentProtocol` + чат со стримингом + два инструмента с подтверждением. S / Low risk. Отклонён: нарушает принятую P2 и не даёт ни одного из двух выбранных вау-моментов — на этом уровне проект просто урезанный Clarc.

### Approach B: Брокер способностей — выбран
См. ниже.

### Approach C: Teach Mode сразу — отложен
B плюс запись Accessibility-дерева в семантический рецепт, сохраняемый как обычный skill. XL / High risk. Отложен: садится поверх B без переделок, но без B садится на песок; «семантический рецепт» это нерешённая задача, на которой можно утонуть на месяцы и не отгрузить ничего.

## Recommended Approach

**B — Брокер способностей.**

Ядро из A, но с границами, которые закрывают принятые премисы архитектурой, а не текстом:

- **`AgentRuntime`** — один `Process`, пайпы stdin/stdout/stderr, NDJSON-декодер, хранение session id, продолжение через `--resume`.
- **`AgentProtocol`** — Swift-протокол, за которым стоит `ClaudeCodeAdapter`. Нормализует поток в `assistantText` / `toolUse` / `toolResult` / `permissionRequest` / `completed` / `failed`. Это исполнение P2: граница ±один агентский CLI.
- **`CapabilityBroker`** — единая точка разрешений и логирования действий. Всё, что трогает файлы, приложения или отправку, проходит здесь и требует подтверждения перед необратимым.
- **Реестр навыков и MCP** — `~/.claude/skills` и MCP-конфиг Claude Code как формат хранения, GUI поверх них для установки и включения. Это исполнение P1 и прямой ответ на `"+ еще mcp сервера"`.
- **Проактивность на событиях присутствия**, без cron. Исполнение P3.

Почему B, а не A: P2 принята, а граница абстракции стоит несколько дней сегодня и переписывание половины приложения через полгода.
Почему B, а не C: C — правильная цель, но она садится поверх B без переделок, а без B не садится вообще.

## Open Questions

1. **Формат рецепта Teach Mode.** Как именно записывать Accessibility-дерево так, чтобы воспроизведение было семантическим («открой папку со вчерашними скриншотами»), а не координатным («клик в 412,388»). Не решено. Это главный технический риск подхода C и его надо прототипировать отдельно, до принятия решения о C.
2. **Безопасность GUI-установки MCP.** Установка чужого MCP-сервера одной кнопкой означает исполнение чужого кода на машине пользователя. Нужна модель доверия (источник, подпись, песочница, объём разрешений), и она не спроектирована.
3. **Границы `AgentProtocol`.** Что именно за протоколом, а что нет. Риск спекулятивной общности: без второго реального CLI граница может оказаться подогнанной ровно под Claude Code и не спасти в нужный момент.
4. **Достоверность оценки Codex.** Прогон ушёл на неизвестную дефолтную модель, `gpt-6-astra` в установленной версии CLI недоступен. Выводы стоит перепроверить, если они начнут определять крупные решения.

## Success Criteria

- Три выбранных сценария (файлы и отправка, утренний разбор дня, управление приложением без API) отрабатывают на чужом Mac без подготовки, с первого дубля.
- Существующий skill, написанный кем-то другим для Claude Code, работает в Runie без изменений.
- Сторонний MCP-сервер ставится из интерфейса человеком, который не открывал терминал.
- Есть 30-секундная гифка с видимыми руками по Mac, которую хочется переслать.
- Замена `ClaudeCodeAdapter` на другой агентский CLI не требует трогать UI-слой.

## Distribution Plan

- Сборка: подписанный и нотаризованный `.app` в GitHub Releases. Нотаризация обязательна — приложение просит Accessibility и Automation, ненотаризованный бинарь на этих запросах умирает на чужой машине.
- Канал: GitHub Releases как основной, Homebrew Cask как второй шаг после первого публичного релиза.
- CI: GitHub Actions на macOS-раннере — сборка, тесты, подпись, нотаризация, публикация релиза по тегу.
- Требования и разрешения (Accessibility, Automation, Full Disk Access при необходимости) описать в README до первого релиза: половина проблем установки будет именно здесь.

- Сохранение текущего положения, при котором `claude -p` и third-party app usage покрыты подпиской. Пересматривается Anthropic, см. Landscape.
- Разрешения macOS: Accessibility, Automation, доступ к файлам.
